数量是 2，空闲 ID 还剩几个？

Node 的 allocatable=2；GPU-A 已被另一个容器使用。现在 kubelet 要给新容器分配 1 个设备。

先预测：healthy={A,B}，allocated={A}，needed=1。available 是 {A,B} 還是 {B}？

展開答案與呼叫點

{B}。這才是設備 ID 層級的“空閒”：健康集合減去 kubelet 的已分配集合。`GetCapacity()`回答資源數量；`devicesToAllocate()`在分配當下挑實際 ID，兩者是不同資料與時機。

可重用設備與首選設備會改變選擇嗎？

會。方法先嘗試 reusableDevices；普通候選是健康集合减已分配集合，再按 NUMA affinity 过滤；条件满足时可选调插件 GetPreferredAllocation，最后仍从可用集合返回设备 ID。

进一步追问：Node 的数量报告仍为 2 时，如果 device manager 的 allocatedDevices 状态丢失或滞后，会发生什么？恢复 checkpoint、ListAndWatch 重建和重启时序都要一起查，不能只看这一行。

写盘失败会让 GetCapacity 返回错误吗？
