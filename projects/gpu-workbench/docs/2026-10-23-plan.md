# GPU Workbench 实现计划

执行方式：本会话连续实现。用户已明确同意设计并要求继续实现及本机部署。
设计依据：2026-10-23-design.md。

## 约束与实现裁定

- 项目独立目录；所有源码、数据、日志和说明集中存放于此。
- Mac 原生运行 local-demo，显示演练标记；Linux 的 k8s-koord-hami 才执行真实 GPU 任务。
- Go + SQLite 单写入服务；任务每次申请一份单卡资源。禁止把演练数据当实测。
- Kubernetes 后端用 client-go；仅支持专用命名空间与受控工作负载模板。
- API 使用团队令牌与幂等键。未知执行状态保留额度。
- 实现 native，由当前会话完成；最后进行独立代码审查。

## Task 1：持久化与任务准入

文件：internal/workbench/model.go、store.go、store_test.go。
接口：Open(path) (*Store,error)、Submit(team,key,Request) (Task,bool,error)、Cancel(team,id)、Tasks(team)、Update(id,state,reason)、Events(team,id)、Quota(team)。
先测试：并发超过额度、幂等重放及请求冲突、重启保留占用、跨团队不可读、终态只释放一次、非法资源请求。
实现：SQLite 事务、唯一索引、认证摘要、事件和任务状态；锁定模型及边界。
验证：`go test ./internal/workbench -run 'TestStore|TestRequest'`，`go test -race ./internal/workbench`。

## Task 2：持续协调和真实集群适配

文件：controller.go、demo.go、kube.go、controller_test.go、kube_test.go。
接口：Backend.Ensure(ctx,Task)、Observe(ctx,Task) (Observation,error)、Cancel(ctx,Task)、Logs(ctx,Task)、Devices(ctx)。
先测试：创建成功后响应超时、取消后不重建、服务重启继续观察、观察失败不释放、Pod 残留时保留额度、外部对象归属冲突。
实现：确定性任务名称；观察优先的循环；故障场景仅在演练后端生效；Kubernetes Job 注入 Koordinator 协议。
验证：`go test ./internal/workbench -run 'TestController|TestKube'`。

## Task 3：API 与本地可用页面

文件：http.go、http_test.go、web/index.html、cmd/workbench/main.go。
先测试：401、403/404、400、409、重复创建、取消、日志、事件、模式与额度指标；限制请求体和错误信息。
实现：Go 内嵌页面，任务提交与取消、设备与额度、状态事件、日志、学习入口；提供 `/healthz`、`/readyz`、`/metrics`。
验证：httptest、浏览器操作、重载与重启后数据保留。

## Task 4：部署与教学

文件：scripts/、deploy/、workloads/、docs/、README.md、Dockerfile、Makefile。
实现：Mac 启停脚本与本地令牌文件；Kubernetes RBAC/StatefulSet/PVC；固定版本 Koordinator/hami-daemon values；在线 CUDA 计算服务与批任务镜像；Prometheus；环境预检；实验脚本及逐课材料。
验证：构建二进制、Go tests/race/vet、脚本检查、YAML 解析、CPU 负载测试、HTTP 冒烟、浏览器截图；真实 GPU 验证单列为未执行。

## Review Focus

1. 身份隔离：团队不能读取或取消其他团队任务。
2. 创建响应不确定：不重复创建，不提前释放配额。
3. 取消与删除残留：确认实际执行结束才释放。
4. 重启与持久化：事件和额度保持一致。
5. 容器协议：schedulerName、标签、单卡资源、NRI 前提和部署权限一致。

## 交付验收

本机地址可访问，完成真实 HTTP 提交/查询/取消以及重启保留数据；离线源码和教学可打开；Kubernetes 文件可解析且有预检和清理说明。没有 Linux GPU 实测的部分明确标记未验证。
