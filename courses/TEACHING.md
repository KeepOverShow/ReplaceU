# 课程深度约定

每节课围绕具体机制，目标是教会读者追踪与判断，不能仅靠术语或算术判断宣称掌握。

1. 从具体请求或故障出发：输入是什么，期待观察什么。
2. 拆参与者：各组件接收什么、读取或改变什么状态、交付什么结果；分清启动配置与运行时调用。
3. 从固定版本源码追到调用点、错误分支和状态写入点；记录 commit、配套关系与版本差异。
4. 解释结果的用途：怎样影响应用处理、排障顺序、容量策略与资源回收。
5. 主动寻找反例：并发、异常退出、底层失败、映射错误、未覆盖 API 与旧状态；区分推断和实测。
6. Archify 图是教学主线，文字、实验和源码索引必须能回到图中的位置；不把图当作运行证据。
7. 给出可复现的程序、命令、预期与原始材料；自动检查只证明它实际覆盖的性质。
8. 将源码事实、教学模型、硬件结果分开标记。没有实际运行时保留待验证，不伪造通过。
9. 以完整题干的选择题和即时解析检验理解：覆盖参与者、状态、分支、证据和工程用途；不要求向对话提交答案。
10. 深内容分层呈现，可分段学习；手机目录、代码横向滚动与即时反馈同样需要验证。

11. 源码导读默认一张问题卡：现场 → 文件与方法 → 原始行号代码 → 模拟断点 → 选择题与即时解析。每次只显示当前卡；异常、并发和调用上下游按需展开。
12. GetCapacity 导读的摘录清单在 `hami/01-excerpts.json`，用 `scripts/check_hami_excerpts.py --kubernetes /path/to/kubernetes --hami /path/to/HAMi --kubelet /path/to/kubelet` 核对固定提交。校验通过不代表代码已在硬件环境执行。
